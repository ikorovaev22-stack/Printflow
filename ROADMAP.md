- [x] Всё на своём сервере в РФ: self-hosted Supabase (база, вход, файлы, realtime) + приложение + Caddy, установка одной командой;
  данные не покидают РФ (152‑ФЗ), работает без VPN
- [x] Ночные бэкапы базы и файлов, копия в S3-хранилище в России, восстановление одной командой
- [x] 152‑ФЗ: согласие на обработку персональных данных при регистрации, политика конфиденциальности
- [x] Скрипт добавления менеджеров (`create-staff`)
- [x] Калькулятор стоимости (визитки, баннеры) и заявка на заказ от клиента, цены в панели
- [x] Файлы в заказе: макеты от клиента, пробники от типографии
- [x] Push- и email-уведомления о статусах, файлах и сообщениях
- [x] История этапов с датами, часовой пояс компании
- [x] Тёмная тема
- [x] Восстановление пароля и подтверждение email через свой домен
- [x] Безопасность: пароль от 8 символов, лимиты попыток и сообщений, лимиты полей, CSP, только растровые логотипы
- [x] Скрипт создания типографии, демо-режим, e2e-тесты

## Перед запуском с реальными клиентами

- [ ] Не включать `DEMO_MODE` и не создавать демо-аккаунты в рабочей базе
- [ ] Своя почта (SMTP) в `deploy/.env` — без неё клиенты не смогут восстановить пароль
- [ ] Копия бэкапов вне сервера: `BACKUP_S3_*` в `deploy/.env` или регулярно забирать `deploy/backups/`
- [ ] Проверить текст политики конфиденциальности с юристом; уведомить Роскомнадзор об обработке персональных данных
- [ ] Vercel + Supabase Cloud: поднять лимиты Supabase Auth, если клиентов много (все запросы идут с адреса сервера)
